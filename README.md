# PhotoCreate 私人攝影棚

提供使用者上傳或選擇角色、指定張數並隨機拍攝寫真的攝影棚。服裝、動作與攝影設定由管理者的素材庫提供；成果可下載、調角度或重新拍攝。另保留本機管理工作檯維護素材與 ComfyUI 環境。

## 啟動

需要 Node.js 24 或更新版本。Windows 可雙擊 `Start-PhotoCreate.cmd`，或執行：

```powershell
npm install
npm run build
npm start
```

伺服器預設監聽 `0.0.0.0:8764`，本機打開 [http://127.0.0.1:8764](http://127.0.0.1:8764)，同一區網的其他電腦使用 `http://這台電腦的IP:8764`。保持啟動程式的視窗開啟。

如果已設定公網連接埠轉送或反向代理，在專案根目錄建立 `.env.local`，填入實際提供給瀏覽器的網址：

```dotenv
PHOTOCREATE_PUBLIC_URL=http://203.0.113.10:8764
```

`Start-PhotoCreate.cmd`、`npm start` 與 `npm run dev` 會讀取此檔案，修改後需重新啟動。HTTPS 反向代理可填 `https://你的網域`，並保留原始 `Host` 標頭。僅允許指定網址的主機與連接埠，寫入請求仍檢查來源網址；本機與區網連線也可繼續使用。`.env.local` 不會提交至 Git。

## 使用者攝影棚

首頁 `/` 會先開啟登入頁 `/login`。第一次啟動時建立管理員帳號 `admin153`，初始密碼 `admin153`；管理員登入後前往 `/admin`，顧客登入後進入自己的攝影棚。後台「顧客帳號」可建立帳號、修改顧客名稱、重設密碼與停用／啟用帳號，也可修改管理員自己的密碼。顧客帳號不提供自行註冊，建立時只能是顧客權限。

角色圖片、拍攝紀錄、原圖和成果綁定帳號，在伺服器逐一檢查歸屬；同一帳號換瀏覽器或電腦仍會看到自己的資料。登入使用 HttpOnly、SameSite=Lax Cookie，登入期限 30 天；HTTPS 入口會加上 Secure。登出撤銷目前裝置的登入，重設密碼與停用帳號會撤銷該顧客所有登入，停用不刪除圖片。重開服務會保留帳號、已修改的管理員密碼與尚未到期的登入。首次顧客登入若仍持有舊版匿名攝影棚 Cookie，會將該瀏覽器的既有角色與拍攝歸入這個顧客帳號。

帳號與登入資料保存在 `data/accounts.sqlite`；密碼使用獨立隨機 salt 與 scrypt 雜湊（N=32768、r=8、p=3），登入 token 只保存 SHA-256。此配置參考 [OWASP 密碼儲存指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。登入錯誤以帳號與實際連線 IP 計數並限制重試；轉送 IP 標頭不提供權限。正式公網登入請透過 HTTPS 代理，讓帳密及登入 Cookie 的傳輸受到加密。

1. 上傳一張角色圖，或選擇管理者提供的預設角色。
2. 指定 1–24 張照片及直式、方形或橫式比例。
3. 按「開始拍攝」，由管理者已套用的服裝、動作、光線、色彩與畫質候選隨機搭配。拍攝進入共用 GPU 佇列，關閉頁面後仍會繼續。
4. 在「我的照片」打開成果，可下載、拍攝不同角度、自訂拍攝或重新拍攝；同時查看原始生成、不同角度拍攝、細節修復各階段的實際提詞、負面提詞、參數與階段成果。尚未送出的階段會標示為預定提詞。
5. 照片可移到「回收區」並還原。照片卡的刪除鈕會移走所有版本；打開照片可在下載按鈕旁只刪除目前版本；刪除後留在檢視視窗，先切到剩餘版本，再切到下一張照片，全部清空才關閉。勾選照片後可批次「刪除所選」，包含各版本。回收區提供「全選／取消全選」，選取目前資料夾篩選下的所有照片，同一張照片的版本合併計算；可還原，也提供單張及批次「永久刪除」。確認後移除回收區版本與拍攝紀錄，之後無法還原。同一組仍在畫廊的版本不會被永久刪除。永久刪除會清理本機中不再被其他拍攝引用的 PhotoCreate 輸出與中間成果；仍被引用的圖片、上傳參考圖與遠端 ComfyUI 檔案會保留。拍攝中的照片需先完成或確認停止。

顧客與管理版均提供單層照片資料夾，保留「全部照片」與「未分類」。產圖前可指定存放位置或建立資料夾；完成後可拖曳照片到資料夾，或勾選後批次移動（手機使用批次移動）。移動會包含同一張照片的原圖、換角度及重製版本，新版本沿用原資料夾。重新命名與刪除資料夾不刪照片，刪除後回到未分類。分類保存在 PhotoCreate 資料庫，不搬動 ComfyUI 實體檔案。顧客的資料夾隨帳號隔離，管理版另有獨立分類，不改動顧客的存放位置。

「我的照片」及回收區的「全選／取消全選」位於資料夾篩選下方、照片列表上方，依目前分類與照片狀態選取，同一張照片的版本合併計算。切換分類或狀態會清空勾選。批次移動、刪除與永久刪除支援超過 100 張的選取，依序以每批最多 100 張送出；永久刪除仍需確認，部分批次失敗時保留未完成的選取供重試。

顧客另有「精選畫廊」。打開照片選好版本，在「畫廊分類」指定分類夾後按「放入畫廊」，固定收錄當下的版本與輸出；後續重拍不會替換精選。同一張成果不重複加入，原圖與不同版本可以各自收錄。畫廊有自己的單層分類夾，支援新增、重新命名、刪除、每頁 24 張、跨頁勾選、批次移動及桌面拖曳分類；資料夾篩選下方提供「全選／取消全選」，包含目前分類的所有分頁，批次操作同樣支援超過 100 張。點縮圖可放大，按「查看照片」回到收錄的版本，下載與不同角度拍攝沿用該版本。「移出畫廊」保留原照片，刪除分類夾只將精選移回未分類。照片進回收區時暫時隱藏精選，還原時一併恢復；永久刪除才移除精選紀錄。畫廊與分類夾皆隨帳號隔離。

畫廊使用較小的縮圖。打開照片後可再點圖片進入放大檢視，支援滾輪縮放、放大後拖曳查看、適合畫面與 100% 實際大小。顧客可用 ←／→ 或上一張／下一張按鈕切換同一張照片保留的原圖與版本；管理版切換目前同一拍攝組的成果，遵守畫廊篩選。切換時重設為適合畫面並顯示目前張數，讀取中保留圖片區域，取得新圖尺寸後才顯示合適倍率，避免暫時跳到 100%；到第一張或最後一張即停止。照片視窗保持固定尺寸，桌面操作區獨立捲動；讀取另一版本的提詞時保留區域高度，避免視窗與版本按鈕跳動。按 Esc 只關閉最上層放大視窗，回到剛才檢視的版本，下載與不同角度拍攝沿用該版本。提詞中的各階段成果也可點圖放大。

按下拍攝後，頁面與每張照片右上角會顯示狀態：安排、排隊、產原圖、換角度、修復及完成。頁面頂端同時顯示本組完成張數，往下看照片時仍會保留；拍攝中每 1.5 秒自動更新，完成後自動顯示成果。排隊、產圖、不同角度拍攝、細節修復、完成與失敗使用不同背景及外框顏色，同時保留狀態文字與圖示；製作中的卡片使用較粗、較深的外框，完成後恢復細框。

選定角色後，即使前一組還在拍攝或修復細節，也可用「排隊拍攝」安排下一組；攝影棚會依序處理各組，張數、角色、比例與資料夾各自保存。新拍攝只產原圖，完成後再依需要拍攝不同角度。重送同一次拍攝不會重複建立。未選角色時可點「先選主角再拍攝」前往角色區；其他無法拍攝的原因會顯示在按鈕下方。更新後需重新啟動服務，才能啟用拍攝中加入下一組。

管理版與顧客版均在正面提詞強調單人、人物只出現一次及單一鏡位。已移除「從參考圖擷取身份與服裝、不複製版面」及「連續場景、單一姿勢」兩段系統指令。負面提詞保留多人、重複人物、三視圖、正側背並排、turnaround、角色設定圖、多姿勢與拼接畫面限制；自訂負面提詞仍保留。原圖、不同角度拍攝與細節修復的實際正負編碼均套用單人限制。舊清單送出與舊照片重產會移除舊的系統限制段落並補上新段落，反覆重產不會重複附加，已保存的實際生成提詞維持原紀錄。提詞降低三視圖產生機會，模型仍可能偏離要求。

使用者只取得自己的拍攝資料與提詞，不會取得工作流、模型路徑或其他使用者的檔案。管理員可勾選並套用開放給顧客的預設角色；未勾選的角色不會出現在顧客選單，也不能用於新的顧客拍攝。尚未保存角色名單的舊版設定沿用全部預設。使用者上傳的角色保持私人，可從「我的角色」刪除；已保存的照片及未完成拍攝保留參考圖副本，不受移除角色影響。

後台「角色參考」、「拍攝清單」與「成果畫廊」只列管理員自己建立的素材與測試拍攝；顧客角色、拍攝及成果保留在各自的帳號。後台 API 同樣限制角色修改、素材讀取、拍攝刪除、重拍、換角度、分類與停止操作的歸屬，「停止全部」僅停止後台自己的任務。管理員提供的共用角色與服裝、提詞候選仍可供顧客使用，共用 GPU 佇列繼續依序處理所有帳號的任務。

顧客可在照片卡或照片視窗停止單張拍攝，也可按「停止我的拍攝」停止自己的待執行與執行中任務。停止經 ComfyUI 確認後，草稿、失敗或已停止的照片可按「繼續拍攝」或「繼續未完成」，接續未完成階段。停止未確認的任務先繼續查詢，避免重複生成；顧客操作不影響其他帳號或 ComfyUI 的其他任務。

管理頁為 `/admin`，只有已登入的管理員能使用管理 API、原始素材路徑與後台。管理員可透過本機、區網或設定好的公網網址登入，原有 Host、同來源與跨網站請求檢查仍保留；顧客帳號不能操作管理 API。素材 ZIP 僅搬移管理素材庫，不包含帳密、登入、私人角色或顧客拍攝；備份全部使用者資料請保留完整 `data` 目錄，包含 `studio.sqlite`、`accounts.sqlite` 與上傳圖片。

開發時執行 `npm run dev`，打開 [http://127.0.0.1:5173](http://127.0.0.1:5173)。

## 管理工作檯使用順序

1. 服裝圖庫：批次上傳衣服圖片，編輯服裝名稱、提詞與標籤。
2. 角色參考：上傳角色圖，保存外貌與辨識特徵的提詞；上傳時可選填 A–Z Cup 和身高（公分），每張角色各自保存，填寫的數值會加入拍攝提詞。顧客上傳也支援；既有角色可在管理圖庫編輯資料，資料 ZIP 會保留尺寸與身高。未填寫不加入額外尺寸要求。
3. 提詞資料庫：搜尋、編輯動作、表情、服裝狀態、場景互動、光線、色彩、畫質；相機角度使用可命名的水平、俯仰與 Zoom 參數，支援 JSON 匯入／匯出。
4. 拍攝工作檯：複選角色與服裝候選。動作、攝影角度、光線、色彩、畫質可複選；每類只顯示摘要卡，點開選擇視窗搜尋、勾選與分頁，每頁最多 8 項，選擇跨頁保留。角色、服裝與可複選的提詞均提供「全選」、「全選搜尋結果」與「清空已選」；提詞全選包含所有分頁。每張照片各取一項，不將多個互斥攝影提詞堆在同一張。
5. 候選組合供管理員測試：角色 × 服裝 × 動作 × 角度 × 光線 × 色彩 × 畫質 × 每組張數，建立清單後手動生成。與隨機寫真各自記住草稿，不影響顧客已套用的設定。表情、服裝狀態、場景互動可單獨選用或補充自由提詞，每組最多 100 張。
6. 拍攝清單：總覽以拍攝組顯示封面、照片張數、素材與完成進度，每頁最多 12 組。進入組內看照片，每頁最多 24 張；可生成整組尚未送出的照片、跨頁選取、逐張檢視提詞或下載原圖。
7. 成果畫廊：按拍攝組篩選、搜尋、放大與下載成果，每頁 24 張，可跨頁勾選不滿意的照片並重製。拍攝組內也可切換「本組成果」。

新增與編輯提詞支援本機、電腦名稱及區網的 HTTP 網址。提詞資料庫、工作檯摘要卡、候選選擇視窗與「存為互動提詞」都使用同一個編輯視窗；一般 HTTP 環境下會使用相容的隨機 ID 產生方式，避免開啟視窗時整頁空白。不同角度、自訂拍攝及重製請求同樣使用此方式。

提詞卡右上方可切換「待確認／已確認」，編輯視窗也可勾選「已確認這個提詞」並保存。確認標記存入 SQLite，JSON 匯入／匯出及 ZIP 搬移保留 `reviewed` 布林值；更新同一 ID 時若未提供此欄位，沿用目前標記。候選選擇視窗右側顯示已確認圖示，左側仍用來選取拍攝候選，兩者分開。確認標記只供管理員追蹤，不限制提詞使用。

拍攝清單、成果畫廊、照片放大視窗與詳細資料中的提詞標籤可直接開啟對應提詞的編輯、關聯成果與臨時試拍視窗。以保存的提詞 ID 及分類找目前資料庫內容；已刪除或自訂的提詞保留原拍攝標籤，不會開啟其他同名提詞。編輯資料庫不改動既有照片的提詞快照。

提詞編輯視窗右側顯示管理員使用這項提詞拍攝的關聯成果，按拍攝快照的提詞 ID 查找，修改名稱或內容仍保留舊關聯。預設隨機展示最多 5 張，少於 5 張就顯示實際數量；超過時按「更多」開啟每頁 24 張的小畫廊，縮圖可放大查看。已刪除、未完成與顧客的照片不會列入。

「臨時試拍」固定左側目前的提詞與尚未保存的修改，其他搭配隨機選擇，角色與服裝從管理員圖庫各取一張；步數與解析度沿用工作檯設定，比例預設沿用工作檯，也可在試拍區獨立選擇跟隨人物參考圖、直式 9:16、橫式 16:9 或正方形 1:1，使用新的隨機 Seed。未保存的新提詞也可試拍。每次只生成一張原圖，完成後立即顯示，不執行轉視角或高清修復。一般提詞保留原圖鏡頭；試拍攝影提詞時將其文字交給原圖模型生成，同樣不需 3D 相機工作流。每次結果列出實際選到的角色、服裝與提詞，不會自動保存提詞或加入正式拍攝清單／畫廊。

試拍需要可存取的本機 ComfyUI 輸出目錄，圖片獨立存放在 `PhotoCreate/_previews/<視窗 ID>/`。關閉編輯視窗、保存或移除提詞、離開頁面時會取消該視窗的單一生成任務並清除全部臨時階段成果；只關閉小畫廊或放大檢視會保留試拍。失去瀏覽器心跳後會自動清理。重開服務依 `data/preset-previews.json` 清理中斷前的試拍，不會恢復生成；ComfyUI 尚未連上時先清除本機圖片，取消暫時失敗與較晚寫入的圖片會持續重試清理。正式照片、上傳參考圖及其他 ComfyUI 任務保留，試拍不主動卸載 GPU 模型。更新後需重新啟動 PhotoCreate，舊服務會在視窗提示重啟。


### 隨機寫真

切換「隨機寫真」，勾選角色並輸入 1–100 張（預設 30）。管理員測試時每張從已選角色中取一個，總張數不因角色增加而增加。預設從全部提詞庫各類抽取一項；有勾選服裝時只在已選服裝中挑選，按「使用全部服裝」則從完整服裝圖庫抽取。必須有至少一張服裝參考圖。

表情、服裝狀態與場景互動都使用複選候選：選了就加入搭配，每張各取一項；清空就不使用，沒有額外的啟用開關。這三類只使用明確選取的候選，即使其餘分類使用「全部提詞庫」也不會自動加入。自由補充提詞、輸出比例、解析度、採樣步數與負面提詞沿用設定。必填分類在選擇視窗保存候選後，會切換為「僅已選候選」；修改選填分類不改動其餘候選範圍。舊版勾選開關會轉為對應的候選清單，原本關閉的分類維持未選。首頁顯示提詞範例，各張實際隨機結果會在生成時保存。

「隨機寫真」同時是顧客候選的編輯入口。選定候選後按「套用至顧客攝影棚」，保存已勾選的預設角色、目前候選、提詞、選填設定、步數、解析度與已存鏡頭預設；顧客自行選角色、張數與比例，完成後可打開照片拍攝不同角度。取消勾選的角色會隱藏，清空角色後套用可關閉全部預設；顧客自己的私人角色仍可使用。清空角色不妨礙套用顧客設定，但管理員測試拍攝至少要選一個角色。「顧客可用的鏡頭預設」只決定角度選單提供哪些預設，不會自動套用到原圖。後續修改草稿、新增或編輯提詞庫不改動已套用內容，需再次套用。刪除素材或提詞時，立即從兩種草稿、目前勾選與顧客已套用名單中移除；舊頁面再次保存或套用也會清理已刪項目。既有照片保留自己的提詞與參考快照。升級時會清理已失效的候選；「套用」按鈕停用時會在按鈕旁顯示具體原因。原有安裝首次升級會保存目前候選設定，之後與管理員測試分開。

目前角色名單、候選內容及拍攝參數與已套用設定相同時，「套用至顧客攝影棚」按鈕變灰；改動後才啟用，還原原值或成功套用後恢復灰色。比較實際候選快照，因此選入提詞的內容修改也需要重新套用；候選順序、確認標記、測試張數、資料夾、Seed 與管理員輸出比例不會被當成顧客設定更新。套用前先完成草稿保存，快速修改後立即套用再重新整理也會保留相同設定。無效設定或後端版本未更新的停用原因仍會顯示。

按「建立隨機清單」只建立草稿，先檢查各張提詞，再到拍攝清單按「生成本組」。兩種模式都不會在建立清單時自動送出。各組合在候選耗盡前不重複；候選不足時允許重複組合並用不同 Seed 生成。固定 Seed 可重現候選順序。重製沿用那張照片已保存的服裝、提詞與比例，不重新隨機搭配。

在服裝圖庫或角色參考中點選圖片，於編輯視窗的「提詞」欄位填寫並保存。角色提詞會加入生成提詞；服裝提詞僅供圖庫備註與搜尋，不自動加入生成提詞。每張拍攝以 `<image1>` 指定角色、`<image2>` 指定服裝，服裝內容由參考圖決定。首頁參考圖區塊只顯示圖片與選擇操作。素材文字仍完整保存在圖庫與拍攝快照。

圖片支援 PNG、JPG、WebP，每張 25 MB；每批最多 50 張、總計 150 MB。圖片名稱取自檔名，僅用來管理圖庫；生成提詞使用角色與服裝參考圖，以及角色、動作與攝影提詞；不自動加入服裝備註、素材名稱或檔名。

## ComfyUI 工作流

### 換環境與連線設定

左下角「工作流與連線設定」提供兩種方式：

- **本機目錄**：選擇此電腦上含 `main.py` 與 `comfy` 的 ComfyUI 目錄，填入服務網址，檢查環境後按「安裝環境」。程式安裝兩份 PhotoCreate 工作流、目前使用的相機加強節點，以及缺少的模型。模型清單顯示來源、容量和已有狀態；可只安裝工作流與節點。下載支援暫停、重開續傳，完成後核對 SHA-256 才放入正式位置。節點更新後需自行重開 ComfyUI，再按「檢查並載入」。
- **ComfyUI 網址**：填入本機或其他主機的網址，使用內建工作流，或選擇對方已保存的兩份工作流。按「測試工作流」檢查原圖、換角度和高清修正的節點、模型與參數，全部通過後才能綁定。綁定時會重新驗證並保存設定；不向 ComfyUI 提交測試生成。缺少的模型與節點需要在該主機安裝。

相機加強版保留俯仰 −90° / −60° 與 Zoom 9 / 10。工作流放在 `user/default/workflows/PhotoCreate/`，不改其他目錄裡的同名工作流；更新相機節點或模型前，原檔保存在 `.photocreate-backups/<安裝 ID>/`。下載暫存使用 `.photocreate.part`；驗證失敗會清空損壞的暫存並保留現有模型，可直接按「繼續安裝」重新下載。已有模型使用檔案大小及 Safetensors 標頭快速檢查；新下載模型會驗證完整雜湊。

「保存安裝設定」只保存新環境的安裝目標。按「檢查並載入」且三個工作流通過後，才切換正式使用的連線與輸出目錄。

內建環境包含 7 個模型，完整下載約 55.9 GB；Git 只保存工作流、節點、模型版本及下載清單，沒有模型權重或個人圖片。詳細來源見 [環境套件說明](bundles/comfyui/README.md)。需要支援 `TextEncodeQwenImage21` 與 `QwenImage21Cache` 的 ComfyUI；檢查會列出缺少的核心節點。這是工作流與依賴的相容性測試，實際生成仍取決於對方主機的 GPU 和可用記憶體。

更換環境前需先暫停拍攝與下載。舊成果沿用原主機的圖片網址，產生圖片時也保存本機輸出位置，避免更換目錄後誤刪另一套環境的檔案。其他主機上的成果仍可查看與下載；標準 ComfyUI API 沒有刪除遠端輸出檔的接口，因此實體檔案需在該主機清理。

預設連線：`http://127.0.0.1:8188`。

預設讀取已保存的：

```text
Qwen Image 2.1/02 Qwen Image 2.1 Uncensored 5090 High Quality - 圖生圖.json
```

從 ComfyUI 的 userdata API 取得工作流，再依執行中服務的 object_info 轉換成 API 格式。需要一個 `TextEncodeQwenImage21`、一個 `KSampler`、一個 `SaveImage`；提詞節點必須連接 CLIP 與 VAE。停用、bypass 或無法辨識的節點會顯示錯誤，避免錯誤轉換。

每次提交會在工作檯的 API 請求中建立兩個 LoadImage，映射：

| 圖片 | 用途 | Qwen 輸入 |
| --- | --- | --- |
| `<image1>` | 角色外貌 | `images.image_1` |
| `<image2>` | 服裝細節 | `images.image_2` |

提詞依 [Qwen 官方的參考圖索引](https://github.com/QwenLM/Qwen-Image-2.1/blob/main/prompt_rewrite/README.md) 與 [ComfyUI 官方範例](https://docs.comfy.org/tutorials/image/qwen/qwen-image-2-1#prompting-for-image-edit) 使用 `<image1>`、`<image2>`，中間沒有空格。服裝圖庫的「提詞」只作備註；不同服裝使用相同的換裝指令，藉由第二張圖指定服裝。

升級時，尚未送出的草稿會更新舊版自動生成的參考圖指令，移除自動附加的服裝備註；已送出與完成的紀錄保持原樣。舊成果重製時同樣修正該段指令，其餘動作、攝影提詞與參考快照維持原設定。自訂完整提詞不作猜測改寫。

沿用原模型、VAE、快取、CFG、sampler、scheduler 與 denoise；步數、參考解析度與 Seed 可在工作檯設定。參考圖保留各自比例。工作檯最上方的輸出比例可選橫式 16:9、直式 9:16、正方形 1:1，或跟隨人物參考圖，並顯示實際寬高。預設跟隨人物圖。

固定比例會調整生成前的空白 latent 尺寸，讓照片直接以所選比例生成。Qwen 2.1 的 latent 為 64 通道、16 倍空間縮放，使用現有 LatentUpscale 調整尺寸；為配合其 8 倍換算，節點傳入實際寬高的一半。角色與服裝參考圖、提詞、模型與採樣設定保持一致。

| 參考解析度 | 橫式 16:9 | 直式 9:16 | 正方形 1:1 |
| --- | --- | --- | --- |
| 1024 | 1536 × 864 | 864 × 1536 | 1024 × 1024 |
| 1536 | 2048 × 1152 | 1152 × 2048 | 1536 × 1536 |
| 2048 | 2560 × 1440 | 1440 × 2560 | 2048 × 2048 |

尺寸維持精確比例並對齊 32 像素。比例與寬高會保存到拍攝快照，匯出 API JSON 與重製都沿用；舊拍攝沿用原來的尺寸。

新拍攝不使用場景參考圖，也不產生 Picture 3 或 Environment 段落。已保存的舊拍攝維持原有參考圖與提詞。

原本 ComfyUI 的工作流檔不會被覆寫。程式在使用者按拍攝、生成、送出所選或臨時試拍時提交生成任務；只開啟編輯視窗不會產圖。草稿的 API JSON 匯出包含參考圖路徑；手動執行前需將圖檔放進 `ComfyUI/input/PhotoCreate/`，或直接由工作檯提交。

### 相機角度與高清修正

顧客與 admin 拍攝前不再提供「套用鏡頭角度」。新拍攝只產 Qwen 2.1 原圖，保留原圖鏡頭；即使舊草稿或瀏覽器偏好保存了開啟鏡頭，新拍攝也不會自動換角度或修復細節。原圖步數沿用拍攝設定。完成後打開照片，按「不同角度拍攝」才執行 `Qwen Multiangle/01 Qwen 2511 - 單圖 3D 相機換角度.json` 與 Qwen 2.1 高清修正，細節修復固定 20 steps。相機角度不加入原圖的攝影描述，而是在相機編碼階段使用本機 `QwenMultiangleCameraNode` 的方向標籤，另將實際水平、俯仰數值與 Zoom 取景級距寫入生成提詞。7°、−9° 等微調不再只留下相同的平視文字；畫面同步顯示目前鏡位。模型依提詞生成視角，無法保證精確的三維幾何角度。補上單人限制後保存為實際提詞。設定中可重新讀取相機工作流；原始 ComfyUI 檔案不會被修改。既有多階段清單仍可接續原來的流程。

相機角度可以命名保存；提詞庫編輯視窗與照片的「不同角度拍攝」都保留拖球、數值、滑桿與快捷選擇。調整區旁提供「已存鏡位」選單，列出完整清單與數量，不再只顯示前五個角度；可直接套用鏡位，或從預設繼續微調，改動後選單標示「自行調整」。管理員可在提詞資料庫新增、修改相機角度，在「顧客可用的鏡頭預設」選入鏡位，再按「套用至顧客攝影棚」提供給顧客；顧客選單沿用已發布的鏡位清單。新操作範圍為水平 0–360°、俯仰 −70–60°、Zoom 0–10；−70° 與 −60° 強烈仰拍仍為試驗。舊 −90° 設定與拍攝紀錄可繼續讀取，載入操作區時調整到 −70°，顯示、狀態與送出數值保持一致。Zoom 使用五個級距，同一組的兩個數字採用相同生成指令：1–2 遠景、3–4 全身、5–6 正常取景、7–8 半身、9–10 特殊局部大特寫。舊值 0 沿用遠景。預設為 5，快捷選單與目前取景標籤同步顯示級距。

Zoom 9–10 以來源照片中央的人物與衣物區域為局部取景目標，由相機模型重新生成近距離構圖，保留完整的轉角成果，再恢復輸出尺寸與修復細節。已移除高 Zoom 固定放大中央區域的裁切，避免切掉頭部與仰拍線索。實測正面可以形成局部大特寫；大幅側轉、俯仰時仍可能失去近距離構圖或視角，屬於試驗取景，一般近景使用 8。更新後需重新啟動 PhotoCreate；新頁面會檢查服務的鏡頭流程版本，遇到舊服務會提示重啟並停用送出。可以用 `node scripts/check-camera-generation.mjs <已完成角度任務 ID> --suite --wait-for-idle` 在本機驗證五個級距、側面仰拍、背面高角度與左側俯拍；`--low-suite` 比較 −70° 正面／側面搭配 Zoom 8／9，`--close-suite` 檢查特殊大特寫的其他視角。`--zoom-suite 0 -70` 在同一角度各拍五個級距一次。加上 `--refine` 可驗證最終高清成果，`--enqueue` 排在現有佇列後面；固定來源與 Seed，使用正式相機建圖函式，產物另存於 `_checks/camera-levels-<ID>/`，不改動任務或原照片。

既有角度保留名稱與 ID，首次啟動換成接近的方向、俯仰與距離。肩後／回眸特寫預設水平 133°、俯仰 31°、Zoom 8；正後方使用水平 180°。新級距升級會把自動預設的一般特寫調整到 8，名稱明確標示大特寫或微距的保留 9／10；半身改用 8，全身改用 3，遠景維持 1。已發布給顧客的自動鏡位同步升級，候選名單不變；已手動調整的鏡位不被自動映射覆寫，已完成拍攝的設定與圖片維持原紀錄。指定身體部位、鏡面效果、逆光或畫面傾斜不能由這三個參數完整表達，編輯時會提示確認鏡位。

成果卡片的「不同角度拍攝」按鈕打開鏡頭調整區，初始為正面、平視、正常取景（0／0／5），可自由調整或套用已存鏡位；管理版可命名新角度，換角度步數與細節修復強度使用選單。來源預覽與實際輸入均使用目前選取的照片／版本／輸出索引：選原圖就以原圖拍攝，選版本 2 就以版本 2 拍攝。送出時保存來源快照與上傳副本；重試該任務使用相同來源，新按一次不同角度拍攝則使用新選取的照片。相機與高清修正分兩階段執行；高清修正只使用轉角成果及固定的內容保留指令，不重新加入角色、服裝、動作、表情或場景提詞。先恢復拍攝的輸出尺寸，再用來源圖 latent 低強度修正；預設修正強度 0.2，可調整 0.05–0.4，較高強度會增加內容改變的機會。管理版勾選「完成後刪除被替換的舊成果」時，成功生成後才刪除所選成果。顧客版保留先前版本。

顧客拍攝不同角度時，左側明確顯示「拍攝來源：原圖／版本 N」，可放大核對。沿用選取照片的 Seed；「重新拍一張」使用新 Seed，產生新的基礎照片。相同來源與 Seed 不保證模型完全保留每個細節，角度幅度與修正強度仍會影響成果。

「自訂拍攝」是獨立入口，動作、服裝、服裝狀態、場景、表情、光線、色彩與畫質各自提供「沿用原設定」，預設全部勾選。取消勾選後，提詞可選官方選項或自行輸入；顧客的官方選單只列出管理員已套用的候選，實際提詞由伺服器依 ID 取回，並保存官方標題。已關閉或刪除的項目無法再送出，開著的選單更新後也會清除失效的選取。每次重送完整提詞，只替換取消勾選的項目；只換服裝圖時，原提詞保持完整、只有 `<image2>` 更換。自訂提詞留白也沿用所選照片的設定。重新勾選的項目會忽略先前輸入的文字或選圖。服裝可用文字描述或選服裝圖；文字以 `The character should wear: …` 加入提詞。服裝狀態可獨立描述袖口、皺褶或衣襬等穿著狀態，只替換 `Clothing state: …`，保留其他提詞與參考圖。模型的 `<image1>` 始終使用拍攝時選的角色參考圖；挑選服裝時將已開放的服裝圖作為 `<image2>`，文字換裝則只傳角色圖。顧客只能看見及送出管理員已套用的服裝候選。照片比例預設沿用上一張，也可單獨改為直式 9:16、方形 1:1 或橫式 16:9，生成時直接設定對應畫布尺寸。自訂拍攝使用 Qwen 2.1 生成一張新照片，不混入鏡頭調整，保留原照並建立新版本。角度版本再次自訂時沿用最近一次基礎／自訂拍攝的設定；舊服務未提供此功能時顯示重啟提示。

自訂拍攝視窗直接顯示拍攝時選取的角色參考圖並標示 `<image1>`。每項沿用設定顯示已選提詞的標題；自訂項目保留顧客輸入全文。成果的「本張使用的提詞」也直接列出搭配，使用照片自己的快照，之後修改或刪除提詞庫不改寫既有照片。

文字服裝指令明確要求完整替換角色參考圖的原服裝，只保留人物外貌。單寫「女僕裝」或「穿一件女僕裝」時採用黑白女僕裝的預設描述，拍攝前顯示實際展開內容，可按「編輯這段服裝描述」修改；明確指定顏色、款式的描述直接沿用，不套用預設。顧客原始輸入與拍攝描述分別保存，重複換装會移除先前衣服的指令。

本機換裝驗證可用 `node scripts/check-photo-customization.mjs <照片任務 ID> <已開放服裝 ID> --enqueue`，各產一張文字換裝與服裝圖換裝的照片。加上 `--maid-check` 可對照短句與明確款式，或用 `--clothing=<描述>` 單獨驗證文字服裝。固定測試動作、場景、表情及完整穿著狀態，使用來源角色與已開放服裝；報告包含實際參考、提詞、展開服裝描述、Seed 與 ComfyUI 請求 ID。輸出另存於 `_checks/custom-photo-<ID>/`，不改動照片任務與資料庫。

每個階段都是獨立的 ComfyUI 請求，只包含該階段的模型；同一批先完成整組目前階段再切換。工作室設定提供「階段切換時釋放 GPU 記憶體」，預設關閉：PhotoCreate 不主動卸載模型，讓顯存充足的電腦保留模型、減少重複載入。開啟時，轉換階段前等待佇列清空，使用 ComfyUI `/free` 釋放模型與快取，再確認切換完成後送出下一階段。設定在每次開始製作時保存，不會中途改動既有製作流程。無論開關都會等待共享佇列的階段屏障；ComfyUI 仍依自己的記憶體管理決定模型能否保留。中間圖保存在 `ComfyUI/output/PhotoCreate/_stages/`，暫停或失敗後按「生成本組」會接續未完成的階段，不重做已完成的原圖。排程由服務端執行，關閉頁面後仍會繼續；重開 PhotoCreate 會查詢原 prompt ID，避免重複提交。拍攝組進度顯示「產原圖」「轉視角」「高清修正」。

舊版合併工作流的照片也可選取最後成果來拍攝不同角度，無需還原未保存的中間原圖。已刪除或不存在的選取照片會被拒絕，不會自動改用別張圖。既有角度任務的來源快照與暫停接續方式保留。

每張原圖完成就會顯示於任務清單，轉視角完成後更新為轉角圖，最後換成高清成果。狀態位於圖片右上角；點圖片或「詳細」可查看目前的產出。暫停或失敗仍保留最近完成的圖片，已刪除的成果不會回退成中間圖。拍攝組封面也會先使用已產出的圖片。

開啟記憶體釋放時，階段切換會在 `pipelineRuns[].modelReleases` 保存釋放請求時間、切換檢查的 prompt ID，以及前後的 GPU/系統記憶體取樣。這是釋放前後的觀測值；執行中的高顯存用量仍可能來自該階段本身的模型與採樣空間。

原圖步數、換角度步數與修正強度各自保存到拍攝快照。相同鏡頭待執行時禁止再次換角度；中止、失敗或待確認都保留舊成果，勾選刪除舊成果時只在新成果成功生成後移除舊檔。

任務包含參考圖與提詞快照，因此後續編輯素材不會改動先前任務。若提交回應中斷，狀態會標為「待確認」，透過 prompt ID 查詢佇列與歷史，避免直接重送造成重複生成。請在 ComfyUI 確認此類任務狀態。移除本程式的素材會保留其檔案供既有任務使用。

## 拍攝組

一次建立就產生一個獨立的拍攝組 ID，因此即使兩組用相同素材、在同一時間建立，也保持獨立。拍攝組可重新命名、整組匯出 JSON、生成草稿／重試失敗照片；已排隊、生成中或完成的照片不會重送。「選取本頁」只選目前分頁可送出的照片；「選取全組」可一次選完組內可送出的照片，選取也會跨頁保留。

首頁的進行中／需要處理分類依組內照片計算。若一組同時有草稿與排隊照片，兩種分類都能找到它；整組照片完成後才會出現在「已完成」分類。

移除拍攝組會一併移除組內的工作檯紀錄；仍有排隊、傳送或生成中的照片時會禁止移除。ComfyUI 的輸出檔案會保留。單獨移除最後一張照片時，空的拍攝組也會一併移除。

右上角「停止製作」可停止 PhotoCreate 目前的全部製作；拍攝組卡片與組內頁面提供「停止本組」，單張任務也有「停止」。傳送途中仍可按停止，尚未送出的任務會停止送出，排隊任務會取消，正在生成的任務會送出中斷要求。已完成的圖片會保留，停止重製也會保留原成果。

生成中的任務先顯示「停止中」，ComfyUI 確認後顯示「已停止」。可在「已停止」分類找到照片，再按「生成本組」或逐張生成，沿用參考圖、提詞與設定重新製作。連線中斷或停止結果不明時維持「待確認」，更新狀態後會繼續確認停止，避免重複生成。停止範圍限於本工作檯記錄的指定任務。

首次升級時，舊版沒有組 ID 的照片會依相近的建立時間與相同角色／場景／攝影設定整理成組，再保存固定的組 ID。這是對旧資料的推估；新的拍攝組使用明確 ID。舊照片的 job ID、ComfyUI prompt ID、狀態、提詞與輸出紀錄都會保留。

## 成果畫廊與重製

畫廊只列出已生成的成果，支援拍攝組篩選、搜尋、每頁 24 張與跨頁勾選。點照片可放大，左右方向鍵切換，Esc 關閉；可下載原圖或查看原提詞。預設顯示每個鏡頭的最新成果，可取消「只看最新版本」查看保留的舊版本。

「重製所選」沿用該次拍攝保存的參考圖、提詞、模型與採樣設定，建立新的任務與隨機 Seed，放回原拍攝組。相同鏡頭有待執行或待確認的重製時，會阻止重複建立。重製請求 ID 可識別重複請求，避免產生多份草稿。

預設勾選「重製完成後刪除舊成果」：新任務成功且有成果圖片後，才刪除被替換的舊成果實體檔案。失敗或待確認時保留舊圖。可取消此選項保留版本。畫廊的「刪除所選」直接刪除所選成果檔案；拍攝提詞與參考圖快照仍保留。

成果刪除僅處理本機 ComfyUI 中 PhotoCreate 產生的輸出，會驗證檔名、目錄及目錄連結。若搬移 ComfyUI，請在 `.env.local` 設定 `PHOTOCREATE_COMFY_OUTPUT_DIR` 為實際 `output` 資料夾，並重新啟動 PhotoCreate；已綁定本機目錄時預設使用該目錄下的 `output`，未設定時沿用 `Z:/AI/comfulUI/ComfyUI-Easy-Install/ComfyUI/output`。舊照片保存的輸出目錄不存在時，僅限同一個本機 ComfyUI 網址可改用目前設定的有效目錄；仍存在的舊目錄及其他主機的紀錄不會改用新目錄。成果刪除與回收區永久刪除均遵守此規則。刪除失敗會在畫廊顯示原因，按「更新成果」可再試。

## 提詞 JSON

範例見 `examples/presets.json`。可以匯入純陣列，或：

```json
{
  "version": 1,
  "presets": [
    {
      "id": "pose-seaside-turn",
      "category": "pose",
      "name": "海邊回眸",
      "prompt": "Standing near the shore, looking over one shoulder, relaxed hands and a natural expression.",
      "tags": ["海邊", "站姿", "回眸"]
    },
    {
      "id": "interaction-window-rest",
      "category": "interaction",
      "name": "靠窗戶",
      "prompt": "Beside a window, gently resting a hand on the windowsill.",
      "tags": ["窗戶", "室內"]
    }
  ]
}
```

分類是 `pose`、`expression`（表情）、`clothing_state`（服裝狀態）、`interaction`（場景互動）、`camera`、`lighting`、`color`、`quality`。相同 id 會更新資料；省略 id 會建立新資料。匯入前會完整驗證整批內容，拒絕重複 id、不支援的分類或缺少名稱／內容。每次最多 10,000 筆，JSON 請求上限 10 MB。

## SQLite 與搜尋

資料庫：`data/studio.sqlite`。圖片：`data/uploads/`。首次取得的來源工作流：`data/workflow-source.json`。

資料分別存在 `assets`、`presets`、`batches`、`jobs`、`meta` 資料表，照片以 `batch_id` 連到拍攝組。使用 WAL 與交易寫入，保持更新的原子性。提詞有分類索引與 [SQLite FTS5](https://www.sqlite.org/fts5.html) trigram 全文索引。搜尋涵蓋名稱、prompt、標籤，多個空格分隔的關鍵字採 AND；一、兩個字的中文短詞用字串搜尋補足 trigram 的最低長度。提詞庫畫面使用伺服器分頁。

第一版是關鍵字與標籤搜尋。未接入 embedding 模型或語意 RAG。未來若需要「找適合海邊夕陽的自然回眸」這類語意搜尋，可在現有資料加上 embedding 索引，再結合類別／標籤篩選；SQLite 仍可作為主要資料庫。語意搜尋的用途是取回已有提詞，最後仍由使用者選擇與確認。

## ZIP 資料搬移

開啟「工作流與連線設定」→「資料搬移」，按「匯出 ZIP」。在新環境安裝並啟動 PhotoCreate 後，於相同分頁選擇資料 ZIP、檢查預覽，再按「匯入資料」。

資料包包含服裝與角色原圖、名稱、保存的提詞、標籤、整個提詞庫（包含 3D 相機名稱、水平角度、俯仰角度、Zoom 與備註），以及目前拍攝設定：角色複選與其他候選選取、隨機模式、選填開關、比例、解析度、原圖步數、鏡頭開關、換角度步數、修正強度、Seed 與補充／負面提詞。若保留了舊版場景圖庫，也會一起搬移。

匯入採合併：既有資料不覆寫，相同圖片與相同資料／提詞內容略過；ID 相同但內容不同時，另建 ID 並重新對應拍攝設定的選取。預設勾選「套用 ZIP 內的拍攝設定」，取消即可保留這台電腦目前的拍攝設定。拍攝進行中可合併圖庫，但需取消套用拍攝設定。重複匯入相同資料包不會持續建立重複項目。

ZIP 使用 `photocreate.json`（`format: PhotoCreate-library`、`version: 1`）與 `images/`，相同原圖只保存一次。匯入先逐一檢查 SHA-256、ZIP CRC、圖片格式、檔案數量與解壓大小，全部通過後才在單一 SQLite 交易寫入；寫入失敗會回收此次複製的圖片。每包 ZIP／解壓後最多 2 GB、每張圖最多 25 MB、最多 10,000 個圖片資料和 10,000 筆提詞，資料清單最多 10 MB。預覽與未下載的 ZIP 暫存 30 分鐘；關閉預覽會移除暫存。

資料 ZIP 不包含成果照片、拍攝任務、模型權重、ComfyUI 目錄／網址或已綁定的工作流。新環境的模型與工作流可用「環境與工作流」安裝／驗證綁定；圖庫搬移不會修改目前連線，也不會呼叫 ComfyUI 或佔用 GPU。

完整備份（包含拍攝紀錄）：先停止工作檯，再複製整個 `data` 資料夾；ComfyUI 的成果檔位於其 `output` 目錄，需另外備份。單獨匯出提詞 JSON 不包含圖片或拍攝任務。
